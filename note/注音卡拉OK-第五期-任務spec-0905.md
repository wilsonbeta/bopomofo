# 注音卡拉OK 第五期 — 任務 spec（0905，Opus partner）

> 母題：注音卡拉 OK；四期已上線 `1b3ccf0`（GitHub Pages）。本期是 Wilson 在 iPad 真機上的兩個回饋，掛同一條線。
> **主線一句話**：輕聲要能存能念（弟弟＝ㄉㄧˋ ㄉㄧ˙ 存不進去），且輕聲的「˙」要照課本擺在音節**上方**，其他聲調維持右側。

## 0. 結案判準

「小孩拼 ㄉㄧ 再點 ˙，字格的點跑到 ㄉ 的正上方；按存，卡片存進去、卡上的點也在上面；點卡片念出 ㄉㄧ 輕聲；整句念『弟弟』第二個字是輕的。」

## 1. 根因（Fable 已查）

代讀表 `syllable-reading.ts` 只有 **30 個**輕聲音節（辭典裡本來就只列 吧／嗎／的 這類）。`ㄉㄧ˙` 不在表裡 → 合法性判定失敗 → 搖頭不存。
但語言事實是：**任何合法音節都可以在詞裡讀輕聲**（弟弟、媽媽、東西、椅子）。所以輕聲的合法性不能用「表裡有 ˙ 條目」判，要用「去掉 ˙ 之後的底音節有沒有任何一個聲調在表裡」判。

## 2. 合法性與發音（改 `lib/deck.ts`、`lib/speech.ts`，本期放行改 lib）

### 2.1 合法性
`isLegalCells`：tone 為 `˙` 時 → 取 base（不含聲調），**base、base+ˊ、base+ˇ、base+ˋ 任一在表裡即合法**。其他聲調規則不變。

### 2.2 輕聲怎麼念（單張、整字 token）
優先序，逐項實測後定：
1. 表裡有 `base˙` 條目 → 用該漢字（現況 30 個）。
2. 沒有 → **送注音字串 `base˙`**（Meijia 對「可解析」的注音字串會念真輕聲：第一期實測 `ㄅㄚ˙` 0.179s vs `ㄅㄚ` 0.248s）。但第二期查過 Meijia 對含 ㄨ／ㄩ／ㄧㄝ 等的注音字串**解析失敗會退化逐符號念**。
   → ★你要做的：對「表裡有任一聲調的 base」全集（約 400 個 base）跑一次 PCM：`say "base˙"` 的時長是否 < `say "base"`（解析成功的輕聲會比一聲短）且不是逐符號退化（時長不接近各符號時長之和）。分類成 **PARSE_OK / DEGRADED**，把 PARSE_OK 清單生成進 `syllable-reading.ts` 旁的一個新表（例如 `LIGHT_TONE_BOPOMOFO_OK: Set<string>`），runtime 查它決定走 2 還是 3。
3. 都不行 → 退回 base 的代讀漢字（找 base 一聲，沒有就 ˊˇˋ 順序第一個有的）——**念的是原調不是輕聲**，這是明知的近似，回報裡列出有多少 base 落到這一層。

### 2.3 整句（▶▶）
整句是漢字串。輕聲卡片：有 `base˙` 漢字用它；沒有就用 2.2-3 的近似漢字（引擎在詞裡自己會不會輕讀，不強求）。**不要在句子裡混入注音字串**（會破壞整句連讀）。

## 3. 「˙」的位置隨狀態換（改 `SyllableBoard.tsx`、`MiniCard.tsx`）

課本排法：**輕聲的點在音節正上方；ˊˇˋ 在右側**。

- **字格**：tone 格是同一個元件，`tone === '˙'` 時擺到三格堆疊的**正上方**（一個較矮的格，高約 44、寬同格 104，只放一個點），其他聲調（含 ˉ）擺右側中格高度（現況）。位置切換用 framer-motion `layout` 動畫（≤ 300ms），讓小孩看到「點跑上去了」。空 tone 時佔位仍在右側（虛線）。
- **卡片**：`tone === '˙'` 時點在符號堆疊上方置中；其他聲調在右側（現況）。
- **符號帶上的 ˙ 鍵**：不動。
