## 1. §4 三個不確定處：查證結果

### §4-A 輕聲注音字串的 PCM 分類 → **不只是「能不能解析」，還有第三種結果：純靜音**

方法：399 個 base（代讀表裡有任一非輕聲條目的 base）各用 `say -v Meijia` 合成
`base` 與 `base˙` 兩個 WAV（22.05 kHz LEI16），用 20ms 窗 RMS 去掉頭尾靜音後比長度。

```
送 base˙ → **完全無聲**              64 個 (16%)   0.031s、峰值振幅 63（正常音節約 25000）
送 base˙ → 比 base 短（真的輕聲）    155 個 (39%)
送 base˙ → 與 base 等長（˙ 被忽略）  173 個 (43%)
送 base˙ → 比 base 長（退化逐符號）    7 個 (2%)
```

spec 問「PARSE_OK 大概有幾個？若 < 50 個，方案 2 價值低」——
**PARSE_OK（真的念出輕聲）有 155 個，遠超過 50**，所以送注音字串這條路是有價值的。

**但真正的發現是那 64 個無聲的組成**：

```
無聲的聲母分布：ㄆ15  ㄊ12  ㄔ10  ㄘ10  ㄎ9  ㄑ8      ← 合計 64，全部
各聲母 無聲/總數：ㄆ 15/17  ㄊ 12/19  ㄔ 10/18  ㄘ 10/16  ㄎ 9/18  ㄑ 8/14
                  ㄅ 0/16  ㄇ 0/18  ㄈ 0/8  ㄉ 0/20  ㄋ 0/25  ㄌ 0/25  ㄍ 0/19  ㄏ 0/18 …
```

**全部、而且只有**六個**送氣聲母** ㄆ ㄊ ㄎ ㄑ ㄔ ㄘ 會無聲；
對應的不送氣聲母 ㄅ ㄉ ㄍ ㄐ ㄓ ㄗ **一個都沒有**。這不是個案，是引擎對「送氣＋輕聲」的固定行為。

意義：加項 3 的兩層規則（表 → 注音字串）遇到「怕」`ㄆㄚ˙`、「太太」`ㄊㄞ˙`
會**整個沒有聲音**——比念錯嚴重。已回報並經追認，加一條守衛：
**輕聲且聲母是這六個時跳過注音字串那一層，改用同 base 的漢字（聲調錯但聽得到）**。
資料剛好收斂成一個六字元常數，所以**沒有建 `LIGHT_TONE_BOPOMOFO_OK` 表**（符合裁定 2）。
依據已依指示寫進 `src/lib/config.ts` 的 `ASPIRATED_INITIALS` 註解。

### §4-B 「˙」移到上方後對齊會不會被撐開 → **沒有被撐開，兩種狀態都差 0.0px**

做法採 spec 建議的第一案：輕聲格 `position: absolute` 浮在三格上方，**不佔 flex 高度**。
不佔高度的代價是它會往上長出白色書頁外，所以左右兩欄一起往下讓 24px
（`COLUMN_TOP_PAD`，由 `SyllableBoard.tsx` 匯出、左欄與 `SymbolBands` **共用同一個常數**）。

同一次操作連續量三個狀態（ˋ → ˙ → ˋ）：

```
ˋ(初始)  pos=right  tone格 x=190 y=454 76×76   ㄉ格 x=68 y=322  midDiff={initial:0, medial:0, final:0}
˙(輕聲)  pos=top    tone格 x=68  y=278 104×38  ㄉ格 x=68 y=322  midDiff={initial:0, medial:0, final:0}
ˋ(切回)  pos=right  tone格 x=190 y=454 76×76   ㄉ格 x=68 y=322  midDiff={initial:0, medial:0, final:0}

輕聲格正對 ㄉ 格上方（x 相同 68、y 較小 278 < 322）: True
切回後與初始完全一致: True
```

三格的 y 座標**完全沒動**（322 不變），中線差 0.0px（spec 要求 ≤ 4px）。
三種 iPad 尺寸在輕聲狀態下也都量過（見 §4-6）。

### §4-C iPad 上點 ˙ 鍵有沒有觸發 → **兩路都到**

`CODE_TO_SYMBOL['Digit7']`（實體鍵）與符號帶上的 ˙ 鍵（`onPress`）各測一次，

### 加項 3：發音退路

| 路徑 | 規則 |
|---|---|
| 單張／整字 token（`speech.ts` `wholeTokenText`） | 表裡有 → 漢字；沒有 → **注音字串**；例外：輕聲＋送氣聲母 → 同 base 漢字（見 §4-A） |
| 整句（`deck.ts` `sentenceReadingOf`） | 表裡有 → 漢字；沒有 → **同 base 任一聲調**的漢字（聲調錯）；連 base 都沒有 → 不放進句子 |

整句那格為什麼不能送注音字串：整句是**一個** utterance，中間混一段注音字串會把連讀打斷。

## 3. 代讀表：兩輪修正

### 3.1 補洞（加項 4 第 1 條）：破音字的**每一個**讀音都算候選

舊規則只認辭典的**第一讀音**，於是「只出現在第二讀音」的音節整格消失。
`白` 的 heteronyms 實際是 `["ㄅㄛˊ","ㄅㄞˊ"]`——第一讀音是 ㄅㄛˊ，
而 ㄅㄛˊ 那格又輸給單音字「帛」，所以舊表裡 **`ㄅㄞˊ` 根本不存在**。
改成每個 heteronym 都登記候選（tier 1 = 第一讀音、tier 2 = 其他讀音）。

### 3.2 挑字規則（加項 4 第 1 條）：**常用度優先於單音性**

舊規則「單音字優先 → 常用 → 筆畫少」會挑到**引擎根本不認得的冷僻單音字**，
而常用的破音字反而排在後面。Wilson 在 iPad 上撞到的 `ㄑㄩㄢ→弮` 就是這樣來的。
新的排序：

```
1. 簡編本收錄的常用字（不管是不是破音字）
2. 其他單音字
3. 其他破音字
同層再看：該音節是不是這個字的第一讀音 → 筆畫少者 → 字碼小者
```

### 3.3 全表 PCM 多數決稽核（加項 4 第 2 條）

**不只稽核可疑的，1331 個音節全部跑。** 每個音節取排序後前 5 個候選字各合成一次，
加上該音節的**注音字串**當硬標準：

```
硬標準命中  796 個 (60%)  某候選字的音訊與注音字串**位元組相同** → 確認就是這個音
多數決      381 個 (29%)  候選字之間音訊相同的分組，取最大組（≥2 人）；組外的字被引擎念錯，剔除
只有一個候選 117 個 (9%)  無從比對，沿用排序第一名
兩兩皆不同   37 個 (3%)  無法判定，沿用排序第一名
```

合成次數約 6400 次、序列跑約 22 分鐘（`say` 不能並行，見 §6）。

**這一輪把 150 個音節的字換掉**（硬標準 111、多數決 39）。前 20 個：

```
ㄅㄚˋ:伯→爸   ㄅㄛˊ:白→帛   ㄅㄛˋ:北→播   ㄅㄠˋ:刨→抱   ㄅㄤˋ:並→蚌
ㄅㄥˇ:繃→琫   ㄅㄧ:幅→逼    ㄅㄧˇ:匕→比   ㄅㄧㄠ:杓→髟   ㄅㄧㄣ:份→彬
ㄆㄛˋ:朴→珀   ㄆㄟˋ:妃→沛   ㄆㄢˊ:胖→槃   ㄆㄥ:亨→怦    ㄆㄧ:匹→丕
ㄆㄧㄝ:撇→瞥  ㄆㄧㄠ:票→漂  ㄆㄧㄢ:片→偏  ㄆㄧㄢˊ:平→胼  ㄆㄨ:仆→噗
```

典型症狀正是新排序帶進來的風險：常用字排到第一，但它是破音字、引擎照**它自己的第一讀音**念
（`ㄅㄚˋ` 挑到「伯」，引擎念成 ㄅㄛˊ）。稽核就是為了擋這個，兩條規則是一組的，缺一不可。

### 3.4 結果

```
舊表 1250 → 新表 1331     新增 81、刪除 0、改字 176
ㄑㄩㄢ → 圈   （say(圈) 0.420s，與 say("圈") 位元組相同）
ㄅㄞˊ  → 白   （say(白) 0.280s，與 say("白") 位元組相同）
新增的輕聲條目：ㄆㄚ˙ ㄙㄚ˙（辭典裡就只有這些）
```

改字 176 個裡有不少是舊表的地雷，例如 `ㄅㄧ` 原本挑到 **屄**（冷僻且不雅）、
`ㄅㄧˇ` 挑到 **妣**、`ㄅㄛ` 挑到 **玻**——現在分別是 **逼／比／波**。
「常用度優先」除了發音正確，順帶把這類字清掉了。

## 6. 三個過程中踩到、值得記一筆的東西

1. **`say` 不能並行。** 我一開始讓 sweep 與 audit 同時跑，兩個 `say` process 互鎖 6 分鐘不動，
   還寫出 64 個只有 header 的殘檔（讓我一度以為量到「無聲」是資料損壞）。
   現在全部序列化，並加上檔案快取（同一段文字只合成一次，中斷可續跑）。
   **之後任何要大量 `say` 的工作都要記得這條。**
2. **聲調符號的墨水天生長在 em 框很上面。** canvas 量出來（PingFang TC 700）：
   `˙ ˇ ˊ ˋ` 的墨水都在基線上方 0.78–0.89em（中心約 0.835em），
   而一般注音（ㄅ）中心約 0.385em。所以 flex 置中會把聲調符號推到框的上緣——
   76×76 的方格裡只是偏高、還看得到；**38 高的輕聲格會整個裁掉**（畫面上是一個空框）。
   已加 `0.475em` 的補償（推導寫在 `SyllableBoard.tsx` 註解），**輕聲格與右側方格都套**
   （裁定：一致性優先；那個高位置其實是字型 metrics 的副作用，不是設計意圖）。
   補償量與格子高度無關，所以 38 高與 76 高共用同一個值。
   **卡片上的聲調照裁定檢查過：不改。** 卡片沒有固定高度的框、沒有裁切問題，
   而且「聲調標在符號右上」本來就是課本排法——置中反而不對。
3. **舊表挑字規則的問題比「念錯」更廣。** 176 個改字裡，`ㄅㄧ` 原本是 **屄**、`ㄅㄧˇ` 是 **妣**。
   雖然漢字永遠不顯示在畫面上、只進語音引擎，但這種字出現在 repo 裡本身就不好。
   「常用度優先」順帶把這類字清掉了。
