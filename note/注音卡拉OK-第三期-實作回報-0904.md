## 1. 【Wilson 要看】三聲連讀變調的 F0 證據

用 `say -v Meijia -o x.wav --file-format=WAVE --data-format=LEI16@22050` 產 PCM，
再用 numpy 算基頻（F0）輪廓：40ms 窗 / 10ms hop，先用 RMS > 300 濾掉無聲幀，
每幀做自相關、在 70–400 Hz 對應的 lag 區間取峰（峰值 / c[0] > 0.3 才採信），
最後對有聲幀序列做線性擬合取 slope。

```
參考型（單獨念）
  馬 (三聲)   start 220.5 → end 141.3 Hz   slope -4.94   ← 降到低，典型三聲
  麻 (二聲)   start 210.0 → end 200.5 Hz   slope -0.50
  媽 (一聲)   start 225.0 → end 220.5 Hz   slope -0.37   （高平）

句子裡的第一個音節
  「馬好」syl1  start 210.0 → end 242.3 Hz  slope +2.23   ← 上揚
  「麻好」syl1  start 208.0 → end 234.6 Hz  slope +2.19   ← 與上一行幾乎完全重合
  「媽好」syl1  start 275.6 → end 275.6 Hz  slope +0.18   ← 明顯不同（高平）
```

**白話**：「馬好」的第一個字，音高走勢跟「麻好」（真的是二聲）幾乎一模一樣，
跟單獨念的「馬」（slope −4.94，往下掉）完全相反。
也就是小朋友卡片上寫 **ㄇㄚˇ**，整列播放時聽到的是 **ㄇㄚˊ**。

**Wilson 裁示：「變調沒關係，這樣才自然」→ 預設 `SENTENCE_SEPARATOR = ''`（自然連讀）。**
這個取捨連同上面的數字，一字不漏寫在 `src/lib/config.ts` 的註解裡，
免得日後有人看到「聲調念錯」以為是 bug 又去修。

**擋掉變調的辦法只有標點，空白無效**（同一組 PCM 實測）：

```
分隔符        文字      時長      syl1 slope   syl1 end     三聲有沒有保住
（無）        馬好      0.542s    +2.23        242.3 Hz     ✗ 變成二聲
全形空白      馬　好    0.542s    +2.23        242.3 Hz     ✗ 引擎直接忽略（與無分隔等長）
半形空白      馬 好     0.542s    +2.23        242.3 Hz     ✗ 同上
~            馬~好     0.542s    +2.23        242.3 Hz     ✗ 同上
全形逗號 ，   馬，好    0.914s    -3.59        163.3 Hz     ✓
半形逗號 ,    馬,好     0.914s    -3.59        163.3 Hz     ✓
頓號 、       馬、好    0.914s    -3.59        163.3 Hz     ✓
分號 ；       馬；好    0.914s    -3.59        163.3 Hz     ✓
間隔號 ·      馬·好     0.914s    -3.59        163.3 Hz     ✓
```

標點類效果**完全相同**（0.914s、slope 一致到小數點後兩位），選哪個都一樣。

## 3. §5 三個不確定處：查證結果

驗證方式：`onboundary` 用**最小 html**（`scratchpad/probe3/index.html`，只有一個 `window.run()`，
無 React、無專案程式碼）＋ CDP `Runtime.evaluate({userGesture: true})` 實跑；
發音內容用 `say` 產 PCM 後用 numpy 分析。**沒有查文件。**

### A. `onboundary` 對 zh-TW / Meijia → **會觸發、索引完全正確，但時序只有插了標點才可用**

Chrome 152 / macOS 26.1，指名美佳。`name` 一律 `'word'`，中文**逐字**觸發、`charLength: 1`：

```
不插分隔符（＝現在的預設）
  "貓媽蜜"        end=831ms   (charIndex, elapsed) = (0,126) (1,809) (2,809)
  "貓媽蜜"（重跑） end=837ms                          (0,101) (1,806) (2,806)
  "貓媽蜜"（重跑） end=837ms                          (0,101) (1,816) (2,816)
  "貓媽蜜八他哥"   end=1450ms  (0,106) (1,703) (2,703) (3,703) (4,895) (5,1407)
  十個字           end=2360ms  (0,99) (1,697) (2,697) (3,697) (4,878) (5,1326) (6,1326) (7,1988) (8,1988) (9,1988)
  "貓"（單字）     end=433ms   (0,337)      ← 連單字都是快念完才回報

插了逗號
  "貓，媽，蜜"        end=1519ms  字的 boundary 在 111 / 719 / 1252
  "貓，媽，蜜，八，她" end=2704ms  101 / 731 / 1243 / 1819 / 2341（間隔 630/512/576/522ms）
```

**索引是對的**（0..n-1 逐字、charLength 1，spec §3「一張卡對到剛好一個字」成立）。
**但不插分隔符時事件成批到達**：三個字的句子裡第 2、3 個字的 boundary 在 809ms 一起抵達，
而整句 831ms 就結束——照這個時序高亮，畫面會是「第一張亮一下，最後 20ms 第二三張一起亮」。
四次重跑數字幾乎相同（±10ms），不是暖機假象；`rate: 0.9` 也一樣。

→ 預設路徑（`''`）**不做逐卡高亮**，退回整列淡發光。**沒有用估時長假裝同步。**

### B. 一個 utterance 串多字會不會亂讀 → **會：三聲連讀變調**

證據見 §1。另外排除掉的嫌疑：

- **輕聲化不嚴重**：「媽媽」0.485s vs 兩個孤立「媽」相加 0.527s，只短 8%。
- **破音字風險本來就低**：`SYLLABLE_READING` 1250 筆代讀字裡，
  `一 不 了 的 得 地 著 和 子 頭 們 麼 兒 個 上 下 來 去` **一個都沒有**（第一期挑字時已避開）。
- 句子整體比各字相加短 15–25%（貓媽蜜 0.717s vs 0.850s）是正常的句末拉長消失，不是問題。

**附帶推翻 spec 一條**：§3 說「句尾可加一個句號給引擎當語氣結尾」，**實測完全無效**：

```
"貓媽蜜" 0.717s  vs  "貓媽蜜。" 0.717s   前綴位元組完全相同（identicalPrefix = True）
```

句號在**句尾**被引擎整個忽略。已依裁示刪除，程式裡沒有加句號。
（同一個句號放在**字間**倒是有效，見 §1 的分隔符表。）

### C. 卡片拿掉框後拖曳好不好抓 → **不用調 `distance`，實測通過**

spec §2 拿掉的是卡片**內部四格的框**，卡片本身的外框、白底、固定寬度都保留，
所以指標事件的接收者沒變、感應區大小沒變；變的只有高度隨內容縮短。

  C_opacityDuringDrag = "0.4"

   可以讓字格邊框先變成淡灰（不擋操作、不出文字）。
3. **卡片顏色深淺可以帶聲調資訊**：現在四類顏色只表示聲母／介音／韻母，
   聲調只有右邊一個小符號，投影到電視上很小。
4. **`onboundary` 的批次行為值得記一筆**：這是引擎層級的特性，
   之後任何「跟著語音跑」的需求都會撞到，別再重驗一次。
