## 2. §5 四個不確定處：查證結果

### 5-1 `@dnd-kit/sortable` 在 Next 16 + React 19 下相容嗎 → **相容，可以用，不需要討論**

```

@dnd-kit/sortable@10.0.0 peerDependencies = { react: '>=16.8.0', '@dnd-kit/core': '^6.3.0' }

├─ @dnd-kit/sortable@10.0.0

**證據 B：StrictMode 雙次 mount 下真的能拖。** `next.config.ts` 本來就是 `reactStrictMode: true`，
dev 模式下 effect 會跑兩次。probe 頁在 mount effect 裡累加計數，確認確實雙次，然後送真滑鼠拖曳：

### 5-2 `active`（字格高亮）與 `playing`（卡片高亮）會不會打架 → **會，但只要「單一 signal ＋ 停止責任集中」就不會；已實作並實測**

原本的隱憂是對的：這兩套 state 各自被非同步迴圈寫，取消之後很容易殘留。
我的做法是**只留一顆取消信號 `signalRef`**，單張播放與整列播放共用；
並把「清狀態」的責任**全部收進 `stopPlayback()`**——被中斷的迴圈只負責 `return`，
一行 state 都不碰（`page.tsx` 每個 await 後面都有 `if (signal.cancelled) return;`）。
`onToken` 也再擋一次 `if (!signal.cancelled)`，避免 cancel 之後還有慢一拍的 `onstart` 把高亮點回去。

實測（整列播放跑到第一張的整字 token 時按停）：

### 5-3 `Cmd+S` 要 `preventDefault`，Chrome / Safari 都攔得到嗎 → **Chrome 實測攔得到；Safari 需人工**

probe 頁掛 `keydown` handler，`(e.metaKey||e.ctrlKey) && e.code==='KeyS'` 時 `preventDefault()`，
用 CDP 送真實的 Cmd+S / Ctrl+S（`modifiers=4` / `modifiers=2`）：

```

ctrlS : {"handlerSeen": 1, "defaultPrevented": true}
afterCmdS_downloadEvents : []      ← 沒有觸發任何「儲存網頁」的下載
```

Chrome 152 / macOS 26.1：handler 收得到、`defaultPrevented` 為 true、瀏覽器的存檔動作沒有發生。
**Safari 沒跑到**（原因見 §5 待裁 1，與第一期同一個權限卡點）。

實作用 `e.code === 'KeyS'`（實體鍵位）而不是 `e.key`，跟第一期的注音鍵表同一個理由——不受輸入法影響。

### 5-4 Safari 下載是否需要把 `<a download>` 加進 DOM → **Chrome 實測「兩種寫法都行」；Safari 需人工，我選了嚴格較安全的那邊**

probe 頁放兩顆鈕，一顆不 appendChild 直接 `a.click()`，一顆 appendChild → click → remove。
用 CDP `Browser.setDownloadBehavior(eventsEnabled=true)` 攔下載事件並實際落檔：

```

                     "probe-attached.json", "probe-attached.json"]

**Chrome 上 detached 也能下載，所以 spec 這一條在 Chrome 是不必要的。**
但 Safari 我驗不到，而「加進 DOM」在 Chrome 已證實無害，所以 `downloadJson()` 採 attached 寫法，
另外把 `URL.revokeObjectURL` 延後 4 秒（Safari 有立刻 revoke 導致空檔的已知風險，這條我也沒能實測，

## 3. 查證途中撞到的兩個真 bug（spec 沒預料到，都已修）

### 3-1 【本期新寫的 bug，我自己踩到自己修】卡片重整後全消失

第一版把「localStorage 讀完了沒」放在 `useRef`。同一次 commit 裡 effect 是照宣告順序跑的：

1. 讀取 effect：`setDeck(loadDeck())`（拿到 2 張卡）、`hydratedRef.current = true`
2. 寫入 effect（同一批）：看到 `hydratedRef.current` 已經是 true，於是拿**還沒更新的 `deck = []`** 去 `saveDeck([])` → **localStorage 被洗掉**
3. StrictMode 第二次 mount 的讀取 effect：`loadDeck()` 這時讀到的是被洗掉的空值 → 卡片真的沒了

實測抓到的原始輸出（修之前）：

```
T3_localStorage      : {"version":1,"cards":[{...ㄅㄚˇ...},{...ㄔㄨㄤˋ...}]}   ← 重整前有資料
T3_cardsAfterReload  : []                                                    ← 重整後全空
```

修法：`hydrated` 改成 **state 不是 ref**——它要跟 `deck` 在同一次 render 才一起生效，
寫入 effect 於是不可能拿到「hydrated 已 true 但 deck 還是舊值」的組合。修後：

```
T3_cardsAfterReload : [{"syms":"ㄅ||ㄚ|ˇ"},{"syms":"ㄔ|ㄨ|ㄤ|ˋ"}]
T3_lsAfterReload    : {"version":1,"cards":[{...},{...}]}
```

**這個 bug 只有在 StrictMode（dev）下會把資料真的清光，production 下會自我修復**——
也就是說如果只跑 `yarn build` 不開 dev 實測，這條會漏掉。

### 3-2 【第一期留下來的 bug】首頁一直有 hydration error

§6-1 要求「開頁無 console error」，我一測就撞到——而且**主頁 `/` 本來就有，不是我加的**：

```
Error: Hydration failed because the server rendered HTML didn't match the client.
  ...
  <Page params={Promise} searchParams={Promise}>
    <Flex2 direction={{base:"column", ...}} ...>
      <chakra(div) ... minHeight="100vh" ...>
        <Insertion>
+       <div style={{background:"#FBFBFD"}} className="css-vc58w" ref={null}>
-       <style data-emotion="css-global ad1llf" data-s="">
```

原因：Chakra v3 走 emotion，SSR 階段插入的**全域 reset `<style data-emotion="css-global">`**
在 App Router 下沒有被交回給 Next，client 端就沒有這個 tag，於是 hydration 對不起來。
第一期回報寫 `t1_consoleErrors = []`——我推測那次是在**軟導覽後**量的（hydration 只在硬載入時發生），
所以漏掉了。這不是第一期的疏忽方向問題，只是量測時機。

修法：`providers.tsx` 加 emotion cache registry（`createCache` + `useServerInsertedHTML`），把 SSR 插入的
style 交還給 Next。修後硬重整實測：

```
{"errors": [], "boardExists": true}
```

**這是第一期程式的修正，不在本期 spec 範圍內。如果你認為應該分開處理，我可以把這個 commit 拆出來。**

## 7. 支線建議（只是記著，沒有混進實作）

1. **匯入改成「取代／附加」二選一**。現在整份取代，小朋友互相交換卡片時只能二選一，
   若要「把同學的卡加到我的後面」得手動編 json。做成兩顆圖示鈕就好，不需要設定頁。
2. **卡片列表加一個「洗牌」鈕**。認字練習很吃「換順序再念一次」，現在只能一張一張拖。
3. **整列播放加一個「循環」開關**。念完自動從頭，適合當背景練習；一顆圖示切換即可。
4. **卡片播放中的視覺可以再強一點**。現在是黃底＋黃外框＋放大 1.06，
   投影到電視上小孩可能看不出來；1.15 ＋ 左側跑馬燈條會更清楚。這條要你看過才知道。
5. **`localStorage` 寫入可以 debounce**。目前每次 `deck` 變動就整份 `JSON.stringify` 寫一次，
   拖曳過程中會寫很多次。卡片數量少所以現在完全不痛，但如果哪天卡片破百值得加。
6. **第一期的 hydration error 提醒了一件事**：「無 console error」這條驗收要**硬重整**才量得準，
   軟導覽量不到 hydration 問題。建議寫進之後的驗收慣例。
